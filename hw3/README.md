# HW3. Семантические проверки и типы

Решение основной части HW3 на основе принятого парсера и AST из HW2 для языка **Funny**. Реализованы таблицы символов, проверки имён и типов, проверка вызовов и результатов функций, диагностика с позициями и аннотированный AST в JSON.

**Бонусный вывод типов не реализован:** у параметров, именованных результатов и локальных переменных должен быть явно указан тип.

## Требования и быстрый запуск

Целевая версия — Python **3.13.3**. В командах используется интерпретатор `python3.13` этой версии. Внешние библиотеки, установка пакетов и доступ к сети не нужны. Все команды ниже выполняются из папки `hw3`.

```bash
cd ~/Desktop/hw3
python3.13 main.py examples/typed.funny
python3.13 main.py --test
```

Первая команда анализа выводит JSON с аннотированным AST; вторая запускает весь набор тестов. Альтернативный запуск тестов:

```bash
python3.13 tests/run_tests.py
```

На macOS можно дважды нажать `RUN_TESTS.command`, чтобы проверить проект без ввода команд.

## Использование

```bash
# Минимальный пример
python3.13 main.py examples/sum.funny --ast

# Все ошибки из некорректной программы
python3.13 main.py examples/errors.funny

# Сохранить машинно-читаемый результат; сообщения останутся в терминале
python3.13 main.py examples/typed.funny > result.json

# Компактный JSON
python3.13 main.py examples/typed.funny --compact

# Токены с позициями (режим HW2)
python3.13 main.py examples/typed.funny --tokens

# Программа из стандартного ввода
printf 'function f() returns r: int { r = 0; }' | python3.13 main.py -
```

Код завершения: **0** — успех, **1** — ошибки программы, **2** — ошибка чтения файла или аргументов CLI. JSON выводится в stdout, краткие сообщения `строка:столбец: код: описание` — в stderr. Поэтому JSON остаётся корректным и при наличии ошибок. `--ast` — необязательный совместимый флаг; по умолчанию уже выполняется анализ с выводом AST и списка ошибок. `--tokens` выполняет только лексический анализ.

## Пример языка

```text
function inc(x: int) returns r: int {
    r = x + 1;
}

function check(x: int)
    requires x >= 0
    returns r: int, ok: bool
    ensures ok -> r > 0
    uses temporary: int
{
    temporary = inc(x);
    r = temporary;
    ok = r > 0;
}
```

В Funny из HW2 нет оператора `return`: результаты — именованные переменные после `returns`. Поэтому тип возврата проверяется при присваивании этим переменным и при использовании результата вызова. `returns` содержит хотя бы один явно типизированный результат. Параметров может не быть.

## Поддерживаемые типы и правила

| Конструкция | Правило |
|---|---|
| `int` | Целые литералы и целочисленные значения |
| `bool` | `true`, `false`, результаты сравнений и логических операций |
| `int[]` | Одномерные массивы из HW2; параметр, результат или локальная переменная |
| `func` | Внутренний тип сигнатуры: список типов параметров и результатов |
| `+ - * /`, унарный `-` | Аргументы `int`, результат `int` |
| `< <= > >=` | Оба аргумента `int`, результат `bool` |
| `== !=` | Одинаковые типы `int`, `bool` или `int[]`; результат `bool` |
| `not`, `and`, `or`, `->` | Аргументы `bool`, результат `bool` |
| `a[i]` | `a: int[]`, `i: int`, результат `int` |
| `a[i] = value` | Значение должно иметь тип `int` |
| `x = expression` | Тип значения совпадает с объявленным типом `x` |
| Вызов функции/формулы | Точное совпадение числа и типов аргументов с сигнатурой |
| `if`, `while`, `assert`, `assume` | Условие/предикат имеет тип `bool` |
| `requires`, `ensures`, `invariant` | Предикат имеет тип `bool` |
| `forall(x: type \| p)`, `exists(x: type \| p)` | Переменная объявлена только внутри `p`, тело и результат — `bool` |
| `predicate(args) -> condition;` | Формула с явно типизированными параметрами и результатом `bool` |

Функции с несколькими результатами поддерживаются, как предусмотрено AST HW2:

```text
function pair(x: int) returns a: int, ok: bool { a = x; ok = true; }
function main() returns r: int uses b: bool { r, b = pair(5); }
```

Количество целей присваивания должно совпадать с количеством результатов. Типы проверяются попарно. Обычное выражение производит одно значение; присваивание `a, b = 1` ошибочно. Вызов с несколькими результатами нельзя использовать как операнд арифметики, условие или один аргумент другого вызова.

Унификация конкретных типов реализована в `semantic.unify`: типы совместимы только при структурном равенстве. Для `func` учитываются число и порядок параметров и результатов. Неявных преобразований, включая `bool` ↔ `int`, нет.

## Области видимости и порядок объявлений

- Функции и формулы используют общую глобальную таблицу. Повторное глобальное имя — ошибка.
- Объявления обрабатываются **в порядке исходного текста**, в том числе когда функции и формулы чередуются. Вызов до объявления запрещён. Собственная сигнатура доступна в теле, поэтому прямая рекурсия разрешена.
- У функции своя область: параметры, именованные результаты и локальные `uses`. Повтор имени между этими группами запрещён.
- В `requires` доступны параметры; в `ensures` — параметры и результаты; в теле — также локальные из `uses`. Ссылка на результат в `requires` или локальную в `ensures` не имеет видимого объявления и отклоняется.
- У формулы своя область параметров. Имена другой функции не видны.
- Блоки и ветви создают дочерние области. Синтаксис HW2 не содержит объявлений внутри блоков: локальные объявляются только в `uses`.
- Квантор создаёт дочернюю область и может затенить внешнюю переменную. После квантора прежнее объявление снова доступно, а связанное имя не выходит за пределы тела квантора.
- Локальное имя может затенить глобальное. Если оно обозначает переменную, попытка вызвать его как функцию даёт ошибку.

Неизвестное имя никогда не создаётся неявно присваиванием.

## Диагностика

Ошибка содержит фазу, стабильный код, описание, строку, столбец и смещение от начала текста. Строка и столбец начинаются с **1**, смещение — с **0**. Табуляция учитывается как один символ; позиции считаются по символам текста. Для EOF позиция указывает сразу после последнего символа.

Пример:

```text
function f() returns r: int {
    r = missing;
    r = true;
}
```

Будут выданы обе ошибки:

```text
2:9: E_UNKNOWN_NAME: Unknown name 'missing': no visible declaration
3:5: E_TYPE_MISMATCH: Assignment target 1: expected int, got bool
```

Основные коды:

| Код | Значение |
|---|---|
| `E_UNKNOWN_NAME` | Имя не объявлено в видимой области |
| `E_BEFORE_DECLARATION` | Вызов глобального имени до объявления |
| `E_DUPLICATE_NAME` | Повторное объявление; указана позиция первого |
| `E_MISSING_TYPE` | Локальная переменная без явной аннотации |
| `E_TYPE_MISMATCH` | Ожидаемый и фактический типы не совпали |
| `E_ARGUMENT_COUNT` | Неверное число аргументов |
| `E_RESULT_COUNT` | Неверное число целей присваивания |
| `E_NOT_CALLABLE` | Попытка вызвать переменную |
| `E_FUNCTION_VALUE` | Функция использована без вызова |
| `E_MULTI_VALUE` | Несколько результатов в контексте одного значения |
| `E_SYNTAX`, `E_LEXER` | Ошибка синтаксиса или недопустимый символ |

Семантический проход продолжает проверку других подвыражений, операторов и объявлений. Вызов с неизвестным именем не мешает проверить его аргументы. Для уже ошибочного подвыражения используется служебный тип `error`, чтобы не выдавать каскад одинаковых ошибок.

При лексической или синтаксической ошибке возвращаются ошибки и частичный AST парсера. Семантический проход в этом случае не выполняется. Парсер сохраняет восстановление после нескольких синтаксических ошибок из HW2.

## Формат аннотированного AST для HW4

Выход — JSON-объект с полями:

| Поле | Содержание |
|---|---|
| `format_version` | Версия формата, сейчас `1` |
| `ok` | `true`, если ошибок нет |
| `ast` | Корневой `Module`; структура и имена полей узлов сохранены из HW2 |
| `symbols` | Таблица объявлений: `id`, `name`, `kind`, `type`, `position` |
| `errors` | Массив диагностик; при успехе пустой |

У каждого выражения, включая цель присваивания и условие, есть `position` и `inferred_type`. Имя поля `inferred_type` означает вычисленный проверкой тип **выражения**, а не бонусный вывод типа локальной переменной. Типы объявлений по-прежнему берутся только из явных аннотаций.

Ссылки на имена и объявления связаны через `symbol_id`. Идентификаторы уникальны внутри одного результата анализа и позволяют различать затенённые имена при генерации IR. Порядок их выдачи детерминирован. У ошибочной неразрешённой ссылки нет `symbol_id`.

```json
{
  "kind": "Var",
  "name": "x",
  "position": {"line": 2, "column": 9, "offset": 47},
  "inferred_type": "int",
  "symbol_id": 2
}
```

Простые типы сериализуются строками `"int"`, `"bool"`, `"int[]"`, `"error"`. Сигнатура: `{"kind":"func","params":["int"],"returns":["int","bool"]}`. Несколько результатов вызова: `{"kind":"tuple","items":["int","bool"]}` — это служебное описание списка результатов, а не отдельный тип переменной языка.

`FunctionCall` из HW2 используется и для вызова формулы; вид объявления находится по `symbol_id` в `symbols`. Узел квантора имеет `kind: "Quantifier"` и поле `quant: "forall"` или `"exists"`. У `If` сохранены поля `then` и `else_`. Позиция составного выражения указывает на оператор, вызова — на его имя, доступа к массиву — на имя массива.

Готовый полный результат минимального примера находится в `examples/sum.annotated.json`. Для следующего этапа следует использовать AST только при `ok: true`.

Python API:

```python
from semantic import analyze_text

result = analyze_text("function f() returns r: int { r = 1; }")
assert result.ok
annotated_module = result.ast
json_ready = result.to_dict()
```

## Тесты и файлы

- `tests/positive/`: 10 корректных программ.
- `tests/negative/`: 20 некорректных программ. Рядом с каждой — `.expected.json` с точным числом ошибок, кодами, строками, столбцами и ожидаемыми фрагментами сообщений.
- `tests/hw2/`: 8 положительных и 5 отрицательных исходных тестов HW2.
- `tests/test_semantic.py`: дополнительные проверки областей, унификации, восстановления, приоритетов, типов и ссылок в AST.
- `tests/test_cli.py`: запуск CLI отдельным процессом, stdin, JSON, коды завершения и ошибки чтения файла.
- `tests/run_tests.py`: общий запуск на стандартном `unittest`.

Основные модули: `automata.py` — автоматы HW1; `lexer_spec.py`, `lexer.py` — токены и позиции; `parser.py`, `ast_nodes.py` — расширенные парсер и AST HW2; `semantic.py` — новый семантический проход; `main.py` — CLI. Точная грамматика — в `grammar.txt`, краткий отчёт — в `REPORT.md`.

## Границы основной реализации

Поддерживаемое подмножество типов — `int`, `bool`, `int[]` и сигнатуры функций. Строк, перегрузок, приведений, функций как значений, многомерных массивов и встроенного `length` нет. Массив передаётся аргументом или копируется присваиванием; литералы и создание массивов синтаксисом HW2 не предусмотрены.

Проверяются статические имена и типы. Выполнение программы, доказательство контрактов, анализ инициализации/присваивания результатов на всех путях, деление на ноль и границы массивов не входят в этот проход. Отсутствие инициализации не считается использованием *до объявления*: объявление задаётся заголовком функции. Вывод типов локальных без аннотации отсутствует.
