# HW3 — краткий отчёт

## Задача и основа

Добавлен самостоятельный семантический проход для Funny поверх принятого решения HW2. Сохранены автоматный лексер HW1, рекурсивный спуск, узлы AST, функции с именованными результатами, массивы, формулы и кванторы. Новая логика находится в `semantic.py`; запуск — через `main.py`.

Выполнена основная часть задания. Бонусный вывод типов локальных переменных не реализован: отсутствие аннотации в `uses` даёт `E_MISSING_TYPE`, даже если тип можно было бы получить из присваивания.

## Таблицы символов

`Scope` содержит словарь объявлений и ссылку на родительскую область. Объявление проверяется на повтор в текущей области; поиск идёт от внутренней области к внешней. Каждое корректно добавленное объявление получает уникальный `symbol_id`. Обращение к имени сохраняет этот идентификатор в AST.

Глобальные объявления проверяются в порядке позиций исходного текста. Это необходимо, поскольку HW2 хранит функции и формулы в разных списках. Вызов до объявления отклоняется; сигнатура текущей функции добавляется до проверки её тела, что разрешает прямую рекурсию.

У каждой функции своя область. Параметры доступны в `requires`, результаты добавляются перед `ensures`, локальные — перед телом. Квантор вводит дочернюю область с собственным связанным именем. Затенение во вложенной области разрешено; повтор в одной области — ошибка. Переменные разных функций и связанные переменные кванторов не выходят за свои области.

## Типы и унификация

Выбранное подмножество: `int`, `bool`, `int[]`; внутренний `func` хранит списки параметров и результатов. Типы конкретны и неизменяемы. `unify` проверяет структурное равенство без подстановок и преобразований. Свободных типовых переменных нет, поэтому отдельный алгоритм вывода типов не нужен.

Арифметика принимает `int`, логические операции — `bool`. Упорядочивающие сравнения принимают `int`, равенство — два значения одного поддерживаемого типа. Индекс массива должен быть `int`; тип элемента — `int`. Условия, контракты и тела формул должны иметь тип `bool`.

Вызов проверяется по сигнатуре: число аргументов и тип каждого аргумента. У Funny нет оператора `return`: объявления после `returns` создают типизированные переменные результатов. Присваивания этим переменным проверяются обычным правилом присваивания. При нескольких результатах проверяются количество целей и тип каждой компоненты. Внутри обычного скалярного выражения многозначный вызов запрещён.

## Диагностика и AST

Узлы парсера сохраняют позицию исходного токена: строку и столбец с 1, смещение с 0. В автоматный сканер добавлено исходное смещение токена. Это устраняет неоднозначное восстановление позиции через поиск текста, которое в HW2 могло попадать в пропущенный комментарий. Автоматы и алгоритм распознавания сохранены.

Ошибки имеют стабильные коды, понятное описание, ожидаемый и фактический типы либо данные о проблемном имени. Анализатор собирает несколько независимых ошибок; служебный тип `error` уменьшает каскад сообщений. После синтаксических ошибок возвращается частичный AST без семантического прохода.

Каждое выражение получает `inferred_type`; это тип выражения, вычисленный из явно аннотированных объявлений. `symbol_id` связывает использования с объявлениями. JSON содержит `format_version`, `ok`, `ast`, `symbols`, `errors`. Формат и пример описаны в README; `examples/sum.annotated.json` содержит полный результат. Для HW4 пригоден результат с `ok: true`.

## Проверка

Набор включает 10 положительных и 20 отрицательных программ с явными ожидаемыми кодами, сообщениями и позициями ошибок, исходные 13 тестов HW2, дополнительные проверки областей видимости и аннотаций AST, а также запуск CLI отдельным процессом. Проверяются несколько ошибок за проход, прямые и преждевременные вызовы, число и типы аргументов/результатов, кванторы, комментарии, EOF, stdin и коды завершения.

Запуск: `python3.13 main.py --test`. Используется только стандартная библиотека; целевая версия — Python 3.13.3.

## Ограничения

Нет строк, неявных приведений, перегрузок, функций как значений, вывода типов локальных, встроенного `length` и многомерных массивов. Объявления внутри блоков не добавлялись: `uses` остаётся местом объявления локальных из HW2. Не проверяются инициализация на всех путях, истинность контрактов, границы массивов и деление на ноль. Это семантический анализ имён и типов, без выполнения программы.
