# HW4 — промежуточное представление и оптимизации

Программа принимает исходный код Funny, запускает лексический, синтаксический и семантический анализ из соседней папки `hw3`, а затем строит IR для каждой функции. При ошибках анализа выводятся диагностики HW3, генерация IR не выполняется.

Этапы обработки: анализ исходного кода в HW3, получение AST с типами и `symbol_id`, генерация IR, разбиение инструкций на базовые блоки, оптимизация и расчёт графа конфликтов. `symbol_id` сохраняет различие между объявлениями с одинаковыми именами в разных областях видимости.

## Запуск

Выполняйте команды из папки `hw4`:

```sh
python3 main.py examples/control.funny
python3 main.py examples/control.funny --pretty
python3 main.py examples/control.funny --dot
python3 -m unittest discover -s tests -v
```

Обычный запуск печатает IR до и после оптимизаций, а также метрики. `--pretty` выводит полный JSON формата `funny-ir-v1`, `--dot` добавляет CFG в формате DOT. Исходный текст можно читать из стандартного ввода: `python3 main.py - < examples/control.funny`.

Оптимизации включены по умолчанию. Флаги `--no-const`, `--no-algebra` и `--no-dce` отключают соответственно распространение/свертку констант, алгебраические упрощения и удаление мертвого кода. `--cse` включает поиск одинаковых выражений внутри блока.

## Формат IR и CFG

IR — трехадресный код: инструкция содержит операцию, результат и операнды. Переменные из AST HW3 обозначаются как `v<ID>`, временные значения — как `tN`, метки переходов — как `LN`.

```text
t1 = v2 + 5
v3 = t1
if v4 goto L1 else L2
```

Поддерживаются копирование, арифметические и логические операции, чтение и запись массива, вызовы функций с одним или несколькими результатами, условные и безусловные переходы, `assert`, `assume` и `return`. `if` и `while` переводятся в переходы между метками. Контракты функции представлены проверками: `requires` в начале, `ensures` в конце тела.

Основные конструкции:

| Конструкция Funny | Представление в IR |
|---|---|
| Целые и логические литералы, переменные | Литерал-операнд или ссылка `v<ID>` |
| `+`, `-`, `*`, `/`, сравнения, логические операции | `bin`; унарные `-` и `not` — `un` |
| `a[i]` и `a[i] = x` | `load` и `store` |
| Вызов функции | `call`; вызов с несколькими результатами — `call_multi` |
| `if` и `while` | Метки, `branch` и `jump` |
| `assert`, `assume`, контракты | Проверочные инструкции |
| Результаты функции | `return` с именами выходных значений |

Формула, вызванная как условие, проходит как обычный вызов. Квантор в контракте сохраняется отдельной высокоуровневой инструкцией с аннотированным предикатом.

CFG строится из меток и переходов; в JSON каждый базовый блок содержит инструкции и список блоков-преемников. Формат JSON также включает сигнатуры функций, IR до и после оптимизаций, граф конфликтов, назначенные цвета и метрики.

В JSON формата `funny-ir-v1` у инструкции есть поля `op`, `dest` и `args`; у блока — `name`, `instructions` и `successors`. Для каждой функции также сохраняются параметры, результаты и локальные переменные с типами и IR-именами. Граф `interference` содержит список соседей для каждого значения, `coloring` — назначенный ему номер цвета.

## Оптимизации и метрики

Распространение констант заменяет известные значения переменных внутри блока. Свертка вычисляет выражения из констант, например `2 * 3`; алгебраические упрощения убирают нейтральные операции, например `x + 0`. Локальный DCE удаляет результаты, которые нигде не используются. CSE — дополнительная оптимизация, которая повторно использует одинаковые вычисления в блоке.

Граф конфликтов строится по живости значений в CFG. Жадная раскраска назначает конфликтующим значениям разные цвета. В метриках указаны число инструкций и временных до и после оптимизации и число использованных цветов.

В текстовом выводе видны строки IR и сводные метрики. Для интеграции с дальнейшим этапом используйте JSON; генератор IR и CFG доступны также как Python-функции в `ir.py` (`Generator`, `build_cfg`, `optimize`, `interference`).

## Пример и тесты

В [examples/control.funny](examples/control.funny) есть арифметика, ветвление и цикл. Полный JSON-результат этого примера сохранён в [examples/control.ir.json](examples/control.ir.json): в нём можно посмотреть исходный и оптимизированный IR, CFG, граф конфликтов и метрики.

В `tests/test_hw4.py` находятся тесты:

- `test_ir_and_cfg_cover_control_flow` — проверяет блоки CFG, ветвления и переходы.
- `test_optimized_and_unoptimized_execution_match` — сравнивает результаты IR до и после оптимизаций на нескольких входах.
- `test_optimizations_reduce_instruction_count` — проверяет уменьшение числа инструкций.
- `test_liveness_graph_is_symmetric_and_colored` — проверяет симметрию графа и отсутствие одинаковых цветов у соседей.
- `test_function_call_is_lowered` — проверяет генерацию IR для обычного вызова.
- `test_multi_result_call_is_lowered` — проверяет генерацию IR для вызова с несколькими результатами.
- `test_dce_keeps_values_used_by_array_store` — проверяет, что DCE сохраняет значение, нужное для записи в массив.
- `test_multi_result_definitions_are_in_liveness_graph` — проверяет учёт нескольких результатов вызова в графе конфликтов.
- `test_cse_invalidates_expression_after_operand_write` — проверяет, что CSE не переиспользует выражение после изменения операнда.
- `test_quantified_contract_is_preserved_as_high_level_ir` — проверяет сохранение квантора из контракта в IR.

Для запуска тестов используйте `python3 -m unittest discover -s tests -v`.
